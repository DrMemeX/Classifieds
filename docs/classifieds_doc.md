# I. Общая информация

# Введение

Система представляет собой платформу размещения частных объявлений, предназначенную для поиска предложений и организации взаимодействия между потенциальными покупателями и продавцами.

Пользователи системы могут размещать и редактировать собственные объявления, просматривать предложения других пользователей, выполнять поиск и фильтрацию по различным критериям, обмениваться личными сообщениями, а также оставлять комментарии к объявлениям.

# Функциональные требования

## 1. Пользователь `USER`

Система должна предоставлять пользователю с ролью `USER` возможность:

- регистрировать учётную запись и выполнять авторизацию;
- просматривать и редактировать собственный профиль;
- просматривать список объявлений;
- выполнять поиск и фильтрацию объявлений по различным критериям;
- просматривать публичную информацию о продавцах;
- размещать, редактировать и удалять собственные объявления;
- загружать и изменять порядок отображения изображений собственных объявлений;
- оставлять комментарии к объявлениям;
- удалять собственные комментарии;
- создавать диалоги по объявлениям;
- просматривать список собственных диалогов;
- просматривать историю сообщений;
- обмениваться сообщениями с другими пользователями.

## 2. Администратор `ADMIN`

Система должна предоставлять пользователю с ролью `ADMIN` возможность:

- создавать учётные записи администраторов;
- просматривать информацию о пользователях и объявлениях;
- блокировать и разблокировать пользователей;
- создавать, изменять и отключать категории объявлений;
- блокировать объявления, нарушающие правила платформы;
- удалять комментарии, нарушающие правила платформы.

## 3. Система

Система должна обеспечивать:

- аутентификацию и авторизацию пользователей;
- поиск и фильтрацию объявлений;
- хранение истории сообщений;
- хранение комментариев к объявлениям;
- предотвращение создания нескольких диалогов в рамках одного объявления для одних и тех же покупателя и продавца;
- разграничение прав доступа между пользователями и администраторами;
- целостность данных при выполнении операций.

# Архитектурные решения

Проект реализуется как **модульный монолит** в соответствии с принципами **MVC**.

Используется следующая схема взаимодействия компонентов:

```text
HTTP Request

↓

Controller

↓

Service

↓

Repository

↓

EntityManager

↓

Hibernate

↓

PostgreSQL
```

**Controller** отвечает исключительно за обработку HTTP-запросов.

**Service** реализует бизнес-логику приложения.

**Repository** обеспечивает доступ к данным.

**Hibernate** реализует объектно-реляционное отображение и взаимодействие с базой данных.

**PostgreSQL** используется в качестве основной системы управления базами данных.

# II. Доменная модель

Ниже приведена доменная модель системы, описывающая основные сущности, их назначение, взаимосвязи и бизнес-правила, определяющие поведение приложения.

## Управление пользователями

## 1. User

`User` представляет системную учётную запись, используемую для аутентификации и авторизации.

Сущность содержит системные данные аккаунта, которые не предназначены для отображения другим пользователям.

| Поле        | Описание                                         |
|-------------|--------------------------------------------------|
| `id`        | Уникальный идентификатор аккаунта                |
| `login`     | Логин, используемый для авторизации              |
| `password`  | Хеш пароля                                       |
| `role`      | Роль аккаунта                                    |
| `status`    | Текущий статус аккаунта                          |
| `createdAt` | Дата и время создания аккаунта                   |
| `updatedAt` | Дата и время последнего изменения учётной записи |
| `blockedAt` | Дата и время блокировки аккаунта                 |

Поддерживаемые роли:

- `USER`
- `ADMIN`

При публичной регистрации всегда создаётся аккаунт с ролью `USER`.

Аккаунт с ролью `ADMIN` может быть создан только другим администратором.

Роль аккаунта не может быть изменена после его создания.

### Жизненный цикл аккаунта

Поддерживаемые статусы пользователя:

- `ACTIVE` — аккаунт активен и может использовать систему;
- `BLOCKED` — аккаунт временно заблокирован администратором;
- `DELETED` — аккаунт окончательно удалён пользователем.

Допустимые переходы между статусами:

```text
ACTIVE -> BLOCKED
BLOCKED -> ACTIVE

ACTIVE -> DELETED
```
Статус `DELETED` является конечным. Переход из `DELETED` в другие статусы запрещён.

### Блокировка аккаунта

При блокировке аккаунта авторизация пользователя запрещается, а все его активные объявления переводятся в статус `INACTIVE`.

Данные аккаунта, связанные объявления, комментарии и переписки сохраняются.

После разблокировки объявления не публикуются автоматически. Пользователь самостоятельно активирует необходимые объявления.

### Удаление аккаунта

Удаление аккаунта выполняется по инициативе пользователя.

При удалении `User` переводится в статус `DELETED` и анонимизируется. 
Исходный логин заменяется техническим значением, пароль становится недействительным, а `UserProfile` сохраняется и анонимизируется.
Персональные данные профиля удаляются, при этом сама запись `UserProfile` сохраняется.

Для других пользователей удалённый аккаунт отображается как `Удалённый пользователь`.

Если оба участника диалога удалили аккаунты, связанный диалог и сообщения могут быть удалены фоновым процессом очистки.


## 2. UserProfile

`UserProfile` содержит персональную информацию, доступную другим пользователям системы.

| Поле        | Описание |
|-------------|---|
| `id`        | Идентификатор пользователя и профиля |
| `firstName` | Имя пользователя |
| `lastName`  | Фамилия пользователя |
| `phone`     | Номер телефона |

`User` и `UserProfile` имеют связь один к одному (`1:1`).

Каждый `User` должен иметь ровно один `UserProfile`. Правило распространяется как на аккаунты с ролью `USER`, так и на аккаунты с ролью `ADMIN`.


## Работа с объявлениями

## 3. Category

`Category` представляет категорию объявления и используется для группировки и фильтрации объявлений.

Категории хранятся в базе данных и не являются `enum`, что позволяет управлять их набором без изменения и пересборки приложения.

Категории поддерживают иерархическую структуру произвольной глубины за счёт рекурсивной связи с родительской категорией.

| Поле | Описание                                                                                |
|------|-----------------------------------------------------------------------------------------|
| `id` | Уникальный идентификатор категории                                                      |
| `parentId` | Идентификатор родительской категории. Для категории верхнего уровня значение равно `NULL` |
| `name` | Название категории                                                                      |
| `active` | Доступна ли категория для размещения новых объявлений                                   |


## Бизнес-правила

- Название категории должно быть уникальным.
- Создавать категории может пользователь с ролью `ADMIN`.
- Изменять название категории может пользователь с ролью `ADMIN`.
- Активировать и деактивировать категории может пользователь с ролью `ADMIN`.
- Пользователь с ролью `ADMIN` имеет доступ к просмотру активных и неактивных категорий.
- Пользователь с ролью `USER` может только лишь получить список активных категорий.
- Отключённая категория не может использоваться при создании новых объявлений.
- Категория не может быть отключена, если у неё существуют активные дочерние категории.
- Для отключения родительской категории необходимо предварительно отключить все её дочерние категории.

## Системная категория «Разное»

В системе всегда существует системная категория **«Разное»**. Она используется для объявлений, которые невозможно отнести к другим категориям.

Для категории **«Разное»** действуют специальные ограничения:

- не может быть переименована;
- не может быть деактивирована;
- не может быть удалена.

Таким образом, в системе всегда существует как минимум одна доступная категория для размещения объявлений.


## 4. Region

`Region` представляет административно-территориальную единицу, в пределах которой размещается объявление.

Использование отдельной сущности позволяет централизованно управлять перечнем регионов и использовать их при поиске и фильтрации объявлений.

| Поле | Описание |
|------|----------|
| `id` | Уникальный идентификатор региона |
| `name` | Наименование региона |

Одному региону может принадлежать множество объявлений.

Каждое объявление обязательно относится ровно к одному региону.

Регион используется при поиске и фильтрации объявлений.

### Бизнес-правила

- Наименование региона должно быть уникальным.
- Регион выбирается пользователем при создании объявления.
- Изменение региона допускается только владельцем объявления.
- Поиск объявлений может выполняться с использованием региона.


## 5. Advertisement

`Advertisement` представляет объявление о продаже товара, размещённое пользователем системы.

| Поле | Описание |
|---|---|
| `id` | Уникальный идентификатор объявления |
| `sellerId` | Идентификатор пользователя-продавца |
| `categoryId` | Идентификатор категории |
| `regionId` | Идентификатор региона размещения объявления |
| `locality` | Населённый пункт, в котором находится товар |
| `title` | Название объявления |
| `description` | Описание товара |
| `price` | Цена товара |
| `status` | Текущий статус объявления |
| `createdAt` | Дата и время создания объявления |
| `updatedAt` | Дата и время последнего изменения объявления |

Один пользователь может разместить несколько объявлений.

Одной категории может принадлежать несколько объявлений.

Название объявления ограничено 100 символами. Описание объявления ограничено 1500 символами.

Цена не может быть отрицательной. Значение `0` допускается для товаров, передаваемых бесплатно.

### Жизненный цикл объявления

Поддерживаемые статусы объявления:

- `ACTIVE` — объявление доступно для просмотра и участвует в поисковой выдаче;
- `INACTIVE` — объявление недоступно для просмотра и не участвует в поисковой выдаче;
- `BLOCKED` — объявление заблокировано администратором;
- `DELETED` — объявление удалено владельцем.

Допустимые переходы между статусами:

```text
ACTIVE -> INACTIVE
INACTIVE -> ACTIVE

ACTIVE -> BLOCKED
INACTIVE -> BLOCKED
BLOCKED -> INACTIVE

ACTIVE -> DELETED
INACTIVE -> DELETED
```

Статус `DELETED` является конечным.
Статус `BLOCKED` используется исключительно для модерации объявления администратором.

### Правила работы с объявлением

Владелец может редактировать название, описание и цену объявления в статусах `ACTIVE` и `INACTIVE`.

При редактировании объявления обновляется значение `updatedAt`.

При отключении категории все активные объявления этой категории переводятся в статус `INACTIVE`. Повторная публикация невозможна до активации категории.

При блокировке пользователя все его объявления в статусе `ACTIVE` автоматически переводятся в статус `INACTIVE`.
После разблокировки пользователь самостоятельно переводит необходимые объявления обратно в статус `ACTIVE`.

Удаление объявления выполняется владельцем и переводит объявление в статус `DELETED`. Физически запись из базы данных не удаляется.

Администратор не может редактировать или удалять пользовательские объявления. Для модерации администратор может перевести объявление в статус `BLOCKED`.

Заблокированное объявление может быть переведено администратором в статус `INACTIVE`, после чего владелец самостоятельно переводит объявление обратно в статус `ACTIVE` или удаляет его.

## 5.1. AdvertisementImage

`AdvertisementImage` представляет изображение, связанное с объявлением.

Функционал загрузки изображений является факультативным.

| Поле | Описание |
|---|---|
| `id` | Уникальный идентификатор изображения |
| `advertisementId` | Идентификатор объявления |
| `objectKey` | Ключ или относительный путь к файлу изображения |
| `displayOrder` | Порядок отображения изображения в объявлении |

Одно объявление может содержать от 0 до 5 изображений.

Для одного объявления значение `displayOrder` должно быть уникальным.

Файл изображения не хранится в базе данных. В `AdvertisementImage` сохраняется только ключ, используемый для получения файла из файлового хранилища.

На начальном этапе изображения могут храниться в локальном файловом хранилище. В дальнейшем допускается подключение S3-совместимого хранилища без изменения модели `AdvertisementImage`.

Для работы с изображениями предполагается использование общего интерфейса файлового хранилища с возможностью различных реализаций хранения.

## 6. Comment

`Comment` представляет комментарий пользователя, оставленный под объявлением.

| Поле | Описание |
|---|---|
| `id` | Уникальный идентификатор комментария |
| `advertisementId` | Идентификатор объявления |
| `authorId` | Идентификатор автора комментария |
| `text` | Текст комментария |
| `createdAt` | Дата и время создания комментария |

Один пользователь может оставить несколько комментариев.

Одно объявление может содержать несколько комментариев.

Текст комментария ограничен 500 символами.

### Правила работы с комментариями

`USER` может оставить комментарий только под объявлением в статусе `ACTIVE`.

`USER` может комментировать собственные объявления.

Редактирование комментариев не допускается.

`USER` может удалить только собственный комментарий.

`ADMIN` может удалить любой комментарий в рамках модерации. Редактирование комментариев администратором не допускается.

При изменении статуса объявления связанные комментарии автоматически не удаляются.

Комментарии доступны пользователям только вместе с доступным для просмотра объявлением.

## Общение пользователей

## 7. Conversation

`Conversation` представляет личный диалог между потенциальным покупателем и продавцом по конкретному объявлению.

| Поле | Описание |
|---|---|
| `id` | Уникальный идентификатор диалога |
| `advertisementId` | Идентификатор объявления |
| `buyerId` | Идентификатор потенциального покупателя |
| `createdAt` | Дата и время создания диалога |

Каждый диалог связан с одним конкретным объявлением.

Для одного объявления между одним покупателем и продавцом может существовать только один диалог.

Продавец не может создать диалог с самим собой по собственному объявлению.

### Правила работы с диалогами

Диалог может быть создан только пользователем с ролью `USER` по объявлению в статусе `ACTIVE`.

Новые сообщения могут отправляться только пока связанное объявление находится в статусе `ACTIVE`.

При переходе объявления в статус `INACTIVE`, `BLOCKED` или `DELETED` диалог сохраняется, но отправка новых сообщений запрещается.

Диалог остаётся доступным его участникам для просмотра.

Пользователи не могут вручную удалять диалоги.

При удалении одного из участников диалог сохраняется для второго участника. Удалённый пользователь отображается как `Удалённый пользователь`.

Если оба участника диалога удалили аккаунты, диалог и связанные сообщения могут быть удалены фоновым процессом очистки.

## 8. Message

`Message` представляет отдельное сообщение, отправленное внутри диалога.

| Поле | Описание |
|---|---|
| `id` | Уникальный идентификатор сообщения |
| `conversationId` | Идентификатор диалога |
| `authorId` | Идентификатор отправителя |
| `text` | Текст сообщения |
| `createdAt` | Дата и время отправки сообщения |

Один диалог может содержать несколько сообщений.

Текст сообщения ограничен 2000 символами.

### Правила работы с сообщениями

Отправлять сообщения могут только участники соответствующего диалога.

Отправитель сообщения должен являться одним из участников соответствующего диалога — покупателем (`Conversation.buyerId`) или продавцом (`Conversation.sellerId`).

Отправлять сообщения могут только пользователи со статусом `ACTIVE`.

Отправка сообщений разрешена только пока связанное объявление находится в статусе `ACTIVE`.

Пустые сообщения и сообщения, состоящие только из пробельных символов, не допускаются.

Отправленные сообщения не могут быть отредактированы или удалены участниками диалога.

При удалении аккаунта отправителя сообщение сохраняется. Для других пользователей автор сообщения отображается как `Удалённый пользователь`.

Сообщения отображаются в порядке даты и времени отправки.

`ADMIN` не имеет доступа к личной переписке и не выполняет модерацию сообщений.
